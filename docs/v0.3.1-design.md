# v0.3.1 主动建议机制 — 设计稿

> 立：2026-08-02 | 状态：实施中 → 待 self-validate

## 目标

**问题**：outcome 写完后，用户经常忘记点"✨ 润色"按钮，cv 就停在 `完成「${title}」` 兜底，沉淀质量肉眼可见低。

**目标**：outcome 停笔 1.5s 后，**自动**调一次 polishCv，给 ghost 建议；用户**采纳**或**忽略**，**不强制替换**。

## 设计取舍

| 取舍 | 选 A | 选 B（不选） |
|---|---|---|
| 触发时机 | **debounce 1.5s**（用户停笔后） | 实时（每打一个字都调） |
| 触发阈值 | **outcome ≥ 30 字**（避免短 outcome 浪费 LLM） | 任意长度 |
| 建议形式 | **ghost 预览 + 采纳/忽略** | 直接替换 cv |
| 跟手动润色的关系 | **互斥**（手动润色时关掉建议） | 并存（两路建议） |
| 跟手动改 cv 的关系 | **手动改 = 隐式忽略** | 仍显示建议 |
| 失败处理 | **静默**（手动润色有 toast 提示） | 弹错误 |

## 实现细节

### State

```ts
const [autoSuggestedCv, setAutoSuggestedCv] = useState<string | null>(null);
const [autoPolishing, setAutoPolishing] = useState(false);
const [suggestionDismissed, setSuggestionDismissed] = useState(false);
```

### Debounce useEffect

```ts
useEffect(() => {
  const o = outcome.trim();
  if (o.length < 30 || suggestionDismissed || polishing) return;
  const timer = setTimeout(async () => {
    try {
      setAutoPolishing(true);
      const res = await api.polishCv(task.title, o);
      if (res.polished && res.cv && res.cv !== cv) {
        setAutoSuggestedCv(res.cv);
      }
    } catch { /* 静默 */ }
    finally { setAutoPolishing(false); }
  }, 1500);
  return () => clearTimeout(timer);
}, [outcome, task.title, suggestionDismissed, polishing, cv]);
```

**关键**：
- `res.cv !== cv` — 不重复显示相同建议
- 依赖里加 `cv` — 用户采纳/手动改 cv 后会重跑（让下一轮 outcome 变化重新触发）

### UI 位置

放在 **CV 框上方**（不是 outcome 旁）—— 用户视线从 outcome 移到 CV 框时看到建议，跟原"✨ 润色"按钮形成**"主动建议 + 手动精修"双轨**。

## 风险

- **LLM 成本增加**：每个完成的任务多调 1 次 polishCv（用户没采纳也是 1 次）
  - v0.3.1 范围：先承担这个成本，v0.3.4 一起做"批量润色 + 复用"
- **建议可能跟手动改 cv 冲突**：用 `res.cv !== cv` 防重，**用户主动改 cv 也算"忽略"**（依赖 cv 变化时清空 suggestedCv 的逻辑在 polish 协调中处理）
- **网络延迟导致建议闪**：debounce 1.5s 给了 LLM 充足时间，理论上不会闪；如果出现，可以加 loading 占位

## 验证标准（v0.3.1 验收）

| 标准 | 怎么验 |
|---|---|
| outcome ≥ 30 字停笔 1.5s 后自动出建议 | 自己用 5 个任务测试，肉眼观察 |
| 建议内容质量 ≥ 手动点"润色" | 对比同一 outcome 的两种结果 |
| 采纳/忽略按钮工作正常 | 点 3 次采纳 + 3 次忽略 |
| 手动点"润色"不会双源冲突 | 手动润色后看不到建议 |
| tsc --noEmit 通过 | `npx tsc --noEmit` 0 error |
| 已有测试不破 | `pytest app/tests/ -v` 0 fail（前端无 vitest） |

## 不做的（明确范围）

- ❌ LLM 批量/复用优化 → v0.3.4
- ❌ 多版本建议对比 → v0.6 智能提炼
- ❌ 用户偏好"主动建议"开关 → v0.3 完成后看反馈再决定
