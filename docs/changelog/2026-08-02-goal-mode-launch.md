# 2026-08-02 — 目标模式启动：cockpit 商业化路线定稿

## 状态
**现行版本**（v1 目标档）

## 背景

cockpit 处于 v0.2 MVP 完成阶段，**完成度够 demo**，但定位还是"个人本地工具"，**离"可商业化/可拿给 VC 看"还差一个"产品哲学 + 路线"层**。

2026-08-01 跟 Mavis 一起打磨目标，用 4 轮对话把"目标"从空概念收敛到 v1 目标档。

## 决策：主目标 = "AI 工作流记忆 → 履历生成 OS"

### 为什么是这条路

4 选 1（个人 SaaS / 团队协作 / 述职自动化 / Agent 工作流记忆层），最终选 **C+D 组合**：

- **C（述职/周报/月报/年终/CV 自动化）** 是产品的**终端价值**
- **D（AI Agent 工作流记忆层）** 是产品的**采集方式**

**关键洞察**：单独做 C 必败 — 周报是低频痛苦动作，工具型周报生成器留存必崩。所以 C 必须是 D 的**自然结果**，不是独立产品。

### 用户原话金句

> "周报像是小型的月报、月报像是小型的年终总结"

→ 翻译成产品语言：**一次沉淀，多次输出**。这是 cockpit 的产品哲学核心。

## 差异化（vs mem9.ai）

调研了 mem9.ai（PingCAP 出的"AI Agent 记忆引擎"，从 OpenClaw 爆火）后，**坚决走差异化路线**：

| 维度 | mem9 | cockpit |
|---|---|---|
| 服务对象 | Agent | **人** |
| 记忆颗粒度 | 对话事实级 | **任务/项目级** |
| 输出 | 检索片段 | **履历文档** |

**核心比喻**：mem9 是水管，cockpit 是水龙头。水管解决"记忆怎么存/怎么查"，水龙头解决"用户拿这份记忆去干什么"。

→ cockpit **不抢 mem9 的市场**，应在 mem9 上**长出来**（甚至可以考虑内部用 mem9 做记忆引擎）。

## 阶段路线

```
v0.3  沉淀智能化（4 字段 AI 润色 + 智能追问 + 主动建议）
v0.4  成就库升级（个人全局时间线 + 跨项目 CV 视图）
v0.5a MCP 集成（让别的 agent 调 cockpit）  ← "被调"层
v0.5b Git 集成（commit → 任务自动草稿）   ← "自己捕获"层
v0.6  智能提炼（agent 主动识别"可沉淀的成就"）
v0.7  统一输出引擎（4 种履历形态共享成就库）
v1.0  VC-ready（10 分钟 demo + 商业模式 + 5 个种子用户 30 天留存）
```

**v0.5 拆 a/b 的理由**：MCP 和 Git 集成是正交的两件事，混在一个版本里会让范围模糊、回归压力大。
