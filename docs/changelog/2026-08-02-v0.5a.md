# 2026-08-02 — v0.5a MCP 集成（让 Claude Code / Cursor 调 cockpit）

## 状态
**现行版本**（v0.5a，立）

## 背景

v0.3 / v0.4 让 cockpit "自用完整"——用户能在 cockpit web 里建项目、写任务、沉淀成就、写周报/CV/PR。

但**cockpit 跟其他 agent 是断的**——用户在 Claude Code / Cursor 写代码时，干了啥 cockpit 不知道，沉淀完全靠用户手动复制。

v0.5a = 给 cockpit 加 **MCP server**，让别的 agent（Claude Code / Cursor / Codex / Dify 等）能调 cockpit 的 CRUD。

兑现 GOAL.md 主线"AI 工作流记忆 → 履历生成 OS"的**采集端**——别的 agent 在用户工作流里持续捕获，cockpit 在后台沉淀。

## 决策

### 1. mcp 2.0 SDK

mcp 2.0 API 全变了：
- `Server` 不再支持装饰器模式（`@server.list_tools()` 报错）— 改用构造参数 `on_list_tools` / `on_call_tool`
- `on_list_tools` 收 `(ctx, params)` 2 个参数
- `on_call_tool` 收 `(ctx, params)` 2 个参数，params 是 `CallToolRequestParams`（含 name + arguments）
- 必须返 `ListToolsResult` / `CallToolResult` BaseModel（不是裸 list）
- 协议用 **line-delimited JSON**（不是 Content-Length header，那是 legacy）

### 2. 5 个核心工具

覆盖 cockpit 核心 CRUD：

| 工具 | 用途 |
|---|---|
| `list_projects` | 拿 project_id（add_task 必填）|
| `list_tasks` | 拿 task_id（complete_task 必填）|
| `add_task` | 新建任务 |
| `complete_task` | 完成任务 + 沉淀成就（**关键工具，跟 web 弹窗对齐**）|
| `list_achievements` | 看沉淀（写周报/CV 时调）|

**为什么是 5 个不是 10 个**：
- 5 个覆盖了"看到 → 写 → 完成 → 查"全链路
- 多了反而不好用（用户不知道选哪个）
- v0.5b/v0.6/v0.7 会增量加（create_project / 自动 capture / LLM 润色等）

### 3. stdio transport

- 启动方式：`python -m app.mcp_server`
- Claude Code / Cursor 把它当子进程
- **零端口占用**（vs HTTP 集成）

### 4. 跟 web 共享 SQLite db

MCP server 跟 web app 用同一个 `~/.cockpit/cockpit.db`：
- 用户在 cockpit web 完成的任务 → 立刻在 MCP 里能看到
- Claude Code 通过 MCP 沉淀的成就 → 立刻在 cockpit web 的成就库里看到
- **双向实时同步**
