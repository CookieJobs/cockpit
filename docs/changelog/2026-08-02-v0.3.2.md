# 2026-08-02 — v0.3.2 智能追问补全闭环（在 /report 写周报时主动调出待补）

## 状态
**现行版本**（v0.3.2，立）

## 背景

v0.3.3 + v0.3.4 让"补全"机制扎实了：
- `/api/reminders/pending` 端点拉待补追问
- `/achievements/follow-up` 专页 + `answerFollowUps` API
- 主页 `FollowUpReminder` 组件（小红点 + 跳页）

但 v0.3.2 真正的价值**还没兑现**：用户写周报时**没看到**"我之前有 N 条待补"。补全是回头补的，不是写周报时主动触发的。

v0.3.2 = "写周报时主动调出待补"。

## 决策

### 1. 入口位置：/report 顶部

不在主页加（已经有 FollowUpReminder 徽章），**直接在写周报的工作流里**加 — 用户从主页 → 写周报 → 立刻看到"还有 N 条待补"。

位置在"时间范围 + 模板选择"之上，原因是"补全"应该先于"选模板"——用户可能因为待补多而**先补全再写周报**。

### 2. UI 形态：info 色卡片 + 条目列表

- info 蓝色边框（区别于主操作区）
- 顶部："还有 N 条成就在等你补全追问" + "一键去补全"链接
- 条目：日期 + 标题 + 第一个追问预览 + "等 N 个追问" 提示
- **每个条目都是链接** → 点跳 /achievements/follow-up?focus={aid}（focus 跳到具体成就）

### 3. 0 个待补时不显示

`followUps.total === 0` → 整个 section 隐藏。不打扰"无待补"的用户。

### 4. 跟 follow-up 页的 focus 参数集成

`/achievements/follow-up` 接受 `?focus={aid}` query param —— v0.3.2 立。点 /report 的条目跳过去，自动 scroll/展开到该成就。

**v0.3.2 这次只做 /report 调出端**，focus param 集成留给 follow-up 页 v0.3.2.1（增量改动，1 行）。
