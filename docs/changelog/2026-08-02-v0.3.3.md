## 写测试时发现的 bug

**`app/core/storage.py` `answer_follow_ups` 在 L809-811 无脑升级 cv_status=ready**。

注释说"用户主动补全了 = 数据够用, 自动升级 ready"，但代码**不检查 answers 是否空**。

→ 后果：用户传空 `{"answers": {}}` 调 API，cv_status 也会从 needs_data 升到 ready。这违背了"数据够用"的语义。

**修法**（1 行）：`if answers and any((v or "").strip() for v in answers.values()): a.cv_status = CVStatus.READY.value`

## 关联 Lessons

- 新增 lesson #27（待）：**补全/升级类 API 端点必须验证"输入是否有效"再触发副作用**。`answer_follow_ups` 是个反例：只检查"调了端点"就升级，没检查"补了至少一题"
  - 反推原则: 任何"调接口 → 状态升级"的链路, 升级触发条件应该是"输入有效"而不是"端点被调"
