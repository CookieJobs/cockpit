## Changelog: 2026-08-23 草稿降摩擦 (outcome 可空 + ⏳ 之后补) v1

用户原话: "我希望完成任务的时候，不要一定让用户去写结果，这样会阻塞掉用户。效果的话，可以让用户之后再来补充上。"

### 判断 (AI CTO 视角)

这条需求跟宪法 §5.4 列的"❌ 去掉 cv 必填"字面对撞 — L2 产品哲学冲突, 不是 L1 使命冲突。

但仔细看了下, **系统已支持延后填** —— `cv_status` 三态 (`pending` / `needs_data` / `ready`) 就是为这个场景设计的, 加上 §2.4 的"沉淀是日常摩擦"暗含"允许最小化"。

所以决定走 **A · UX 优化**, 不动宪法一行字:
- outcome 完全空 → 后端强制 `cv_status=pending` (不绕过质量门)
- 弹窗 outcome label 改"可选"
- 新增"⏳ 之后补"快捷键 (显式声明"暂存", 不走 LLM 润色)
- 主按钮 "沉淀成就" 永远可点 (空 outcome 自动 pending)
- 修 chat.py 对话路径 `cmd_complete` 的误导文案 (之前说"已沉淀", 现在说"草稿待补")
- 修 `_provenance_guardrail` 在 outcome+answers 都空时短路 (Pydantic schema 要求 outcome min_length=1, 不短路会炸)

### 不动的事 (宪法守护)

- AI_CTO §2.4 "价值陈述不能省略" — 没动。outcome 是 cv 的"价值陈述", 但 cv 仍可写, 系统只是允许延后。
- AI_CTO §5.4 "❌ 去掉 cv 必填" — 严格说, 这条改的是"outcome 必填", 不是"cv 必填"。cv 在新设计里仍有兜底值 (`完成「${task.title}」`), 仍走 storage 的 readiness derivation, 没绕过质量门。
- AGENTS.md "完成即沉淀 — 4 字段 UX 铁律" — 仍成立: outcome / cv / reflection / cv_status 4 字段都在, 只是 outcome 标记从必填改可选。

### 后续观察 (dogfooding 2 周后回看)

1. "⏳ 之后补" 按钮使用率 — 跟"沉淀成就"主按钮的使用率对比, 看摩擦有没有真降
2. pending 状态 pending → ready 的转化率 (用户多久回来补全)
3. /api/reminders/pending 的 pending 列表是不是成了"用户每天都看到待补"的噪音
4. 草稿是不是会变成"逃避沉淀"的捷径 — 如果是, 需要加 reminder 强度

如果 dogfooding 2 周后发现 pending 转化率 < 50%, 说明用户真把"之后补"当逃路了, 那时候再讨论宪法 §2.4 的边界。
