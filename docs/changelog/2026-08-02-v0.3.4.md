# 2026-08-02 — v0.3.4 润色质量升级（POLISH_CV_SYSTEM 软要求改硬 + few-shot + 反模式）

## 状态
**现行版本**（v0.3.4，立）

## 背景

v0.3.1 主动建议机制让用户更容易"获得" AI 润色，但**润色质量本身没改**。

v0.2 阶段的 `POLISH_CV_SYSTEM` prompt 写的是软要求（"如...动词开头"、"量化优先"）— LLM 实际行为**很随机**，经常返"完成了 XX"这种弱 cv。

v0.3.4 把 prompt 从"软建议"升级到"硬约束 + few-shot + 反模式"三件套。

## 决策

### 1. 软要求 → 硬要求

| 维度 | v0.2 软 | v0.3.4 硬 |
|---|---|---|
| 动词 | "动词开头（如...）" | "必须用强动作动词" + 10 个强动词清单 |
| 弱动词 | 没禁止 | "【严禁】弱动词" + 4 个弱动词禁止清单 |
| 量化 | "量化优先" | "【量化是硬指标】" + 5 种量化模板 |
| 追问 | "信息不够就追问" | "没量化 = 必追问 1-2 个量化问题" + 优先级（影响 > 量化 > 团队 > 时间） |

### 2. 加 few-shot（4 对强/弱对比）

| ❌ 弱 | ✅ 强 |
|---|---|
| "完成了登录 bug 修复" | "定位并修复登录鉴权高优先级 bug, 消除用户登录阻塞, DAU 提升 5%" |
| "参与了 XX 项目" | "主导 XX 项目核心模块设计, 落地 3 个关键功能, 服务日均 50 万用户" |
| "做了 PRD 撰写" | "撰写并推动落地 XX 产品 PRD, 评审通过率 100%, 团队 5 人协同推进" |
| "重构了用户模块" | "重构用户模块拆分 3 个微服务, 接口响应时间从 800ms 降至 200ms, 团队开发效率提升 30%" |

**为什么 few-shot 强过纯文字规则**：
- 规则 LLM 会"软遵守"，例子是"硬模仿"
- 4 对覆盖 4 大常见任务（修 bug / 做项目 / 写文档 / 写代码），相当于"任务类型 → cv 模板"

### 3. 追问优先级（v0.3.4 强化）

按"对 cv 价值贡献度"排：
1. **影响范围**（多少人/多大量）— 第一优先
2. **量化收益**（提升/节省多少）— 第二优先
3. **团队规模**（多少人协同）— 第三优先
4. **时间成本**（用了多久）— 第四优先

之前的追问机制（v0.2）问的是"补充细节"——太空泛。v0.3.4 把"补充细节"细化到"按优先级追问"。

- ✅ `test_polish_prompt_contains_strong_verbs` — 至少 5 个强动作动词
- ✅ `test_polish_prompt_prohibits_weak_verbs` — 至少 3 个被禁止弱动词 + "严禁"标记
- ✅ `test_polish_prompt_contains_quantification_requirement` — 含 "硬指标" 语义
