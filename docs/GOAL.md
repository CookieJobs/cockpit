# Cockpit — 当前目标 v1（2026-08-02 启动）

> **主目标**：把 cockpit 打造成 **"AI 工作流记忆 → 履历生成 OS"** —
> agent 持续捕获用户工作流 → 沉淀成结构化成就库 → 关键时刻一键生成周报/月报/年终/CV。
>
> **核心哲学：一次沉淀，多次输出**。

---

## 一句话定位

cockpit 不做"记忆基础设施"（mem9.ai 已经做了，且爆火）—— cockpit 做 **"工作流 → 履历"**，**服务人，不服务 agent**。

这是 cockpit 跟 mem9 的根上分叉，也是 cockpit 在 VC 故事里能立住的核心差异点。

---

## 两条腿

| 腿 | 路线 | 价值 | 当前进度 |
|---|---|---|---|
| **采集侧（D）** | 工作流记忆层 | 留存 / 日常使用 / 数据积累 | v0.2（对话 + 4 字段沉淀） |
| **输出侧（C）** | 履历生成端 | 变现 / 关键价值兑现 / Demo 杀手锏 | v0.2（周报 workspace 雏形） |

**两条腿相互依赖**：D 沉淀的质量决定 C 输出的天花板；C 输出的价值反向驱动 D 的留存。

---

## 差异化（vs mem9）

| 维度 | mem9（已爆火） | cockpit（要走） |
|---|---|---|
| **服务对象** | Agent（提供 memory API） | **人**（提供 productivity 闭环） |
| **记忆颗粒度** | 对话事实级（"用户在第 3 轮说了什么"） | **任务/项目级**（"用户完成了 X 项目，实现了 Y 价值"） |
| **输入** | 任意 agent 的对话流 | 项目/任务/对话/完成时的成就沉淀 |
| **输出** | Memory 检索片段 | **履历文档**（周报/月报/年终/CV） |
| **价值兑现** | 解决"agent 怎么记住" | **解决"人怎么从记忆里产生价值"** |
| **商业模式** | Memory API 收费（用量计费） | 待定（订阅 / 团队版 / 一手交付） |

**协同姿势**（重要）：cockpit 内部可用 mem9 做记忆引擎（省去自研搜索/向量），自己专注"工作流 → 履历"的产品层。**不抢 mem9 的市场，**在 mem9 上**长出来**。

## 阶段路线

| 版本 | 目标 | 关键交付 | 验证标准 |
|---|---|---|---|
| **v0.3** | 沉淀智能化 | 4 字段 AI 润色 + 智能追问 + 主动建议 + cv_status 三态 | 自己用 2 周，沉淀质量肉眼可见提升 |
| **v0.4** | 成就库升级 | 个人全局时间线 + 跨项目 CV 视图 + 成就统计/筛选 | 1 份能用的真实周报 + 1 份真实月报 |
| **v0.5a** | **MCP 集成** | 让 Claude Code / Cursor 等 agent 调 cockpit | 别的 agent 能在对话里调 cockpit 写任务 |
| **v0.5a.1** | **接入中心** | `/integrations` 一键注册到 Claude Code / Cursor / Trae / Cline / Continue / WorkBuddy，不用手改 JSON | 用户在 cockpit web 点 1 下按钮完成配置，5 个 json agent + 1 个 command agent |
| **v0.5b** | **Git 集成** | commit → 任务自动草稿 | 一次 commit 后能自动生成任务草稿 |
| **v0.6** | 智能提炼 | agent 从对话历史主动识别"可沉淀的成就" | 1 周不主动操作仍能生成 80% 内容的周报 |
| **v0.7** | 统一输出引擎 | 周报/月报/年终/CV 共用成就库 | 4 种形态都能一键出，质量稳定 |
| **v1.0** | **VC-ready** | 10 分钟 demo + 商业模式 + 增长策略 | 1 个 3 分钟 demo 视频 + 5 个种子用户 30 天留存 |

**v0.5 拆 a/b 的理由**：MCP 跟 Git 集成是正交的两件事，混在一个版本里会让 v0.5 范围模糊、回归压力大。拆开后可以并行/串行，灵活度更高。

## 核心产品哲学：一次沉淀，多次输出

> "周报像是小型的月报、月报像是小型的年终总结"

翻译成产品语言：

```
                    ┌─ 周报模板（时间窗 7d, 简洁）
                    │
成就库（单一数据源）─┼─ 月报模板（时间窗 30d, 中等）
  (项目+任务+       │
   成就+复盘)       ├─ 年终模板（时间窗 365d, 详细）
                    │
                    └─ CV 模板（时间窗 N 年, 成就导向）
```

**这意味着**：
- 采集侧只要保证成就库质量
- 输出侧只是数据查询 + LLM 套模板 — **几乎零边际成本**
- 新增一个输出形态（OKR 复盘 / 述职答辩稿）只是写一个新模板
- 用户价值是**指数级**的：每多沉淀一份资产，可生成的报告形态多 N 种

## Agent 角色（产品 + 技术 + 商业）

cockpit 在这个目标推进过程中，**Agent 同时承担 4 个角色**：

| 角色 | 职责 |
|---|---|
| **产品专家** | 定义"一次沉淀多次输出"哲学、UX、模板系统；洞察用户真实需求 |
| **技术专家** | MCP 协议集成、成就库 schema、跨项目时间线、模板引擎；架构选型、风险评估 |
| **差异化顾问** | 盯紧 cockpit vs mem9 的边界（人 vs agent / 文档 vs 片段），防止漂移 |
| **打工人** | 自己作为目标用户画像，先用 1 个月，每周一份周报 + 1 份月报 |

---

## 风险点（提前暴露，不藏着）

1. **mem9 先发优势** — 必须坚守"服务人 / 输出文档"差异化，不能被引去抢"记忆基础设施"市场
2. **本地优先 vs VC 故事** — 商业化时必须补账号/云端/支付，但又不能丢本地优先初心（**"本地版是品牌护城河，云端版是变现引擎"**）
3. **LLM 成本** — 智能提炼 + 多模板生成，每份履历都要过 LLM，单次成本要做账（v0.7 之前先用便宜模型）
4. **单兵作战速度** — VC 故事要"快"，但很多环节（UX 打磨 / 种子用户运营）不能跳过；需要平衡"快"与"扎实"

## 回看节奏

每个 v0.X 完成时做一次"目标健康度"复盘，复盘时问三件事：

1. **这版达成了什么？** — 验证标准是否达标
2. **路线是否要调整？** — 哪个里程碑要前置/后置/砍掉
3. **下个分叉要不要先定？** — 哪些待定项变成必须决策
