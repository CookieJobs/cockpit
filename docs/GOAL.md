# Cockpit — 当前目标 v1（2026-08-02 启动）

> **主目标**：把 cockpit 打造成 **"AI 工作流记忆 → 履历生成 OS"** —
> 用户授权的数据源 → 带来源证据的成就候选 → 用户确认的结构化成就库 → 关键时刻一键生成周报/月报/年终/CV。
>
> **核心哲学：一次沉淀，多次输出**。

---

## 一句话定位

cockpit 不做"记忆基础设施"—— cockpit 做 **"工作流 → 履历"**，**服务人，不服务 agent**。

这是 cockpit 与 agent memory 产品的根上分叉，也是 cockpit 能长期立住的核心差异点。

## 首要用户画像

首个服务对象是**同时并行 3–5 个项目、每周需要写周报、半年内可能述职或求职的知识工作者**。维护者本人必须先在这个画像中连续自用；其他人群只作为后续研究对象，不能反向稀释首条核心路径。

---

## 两条腿

| 腿 | 路线 | 价值 | 当前进度 |
|---|---|---|---|
| **采集侧（D）** | 工作流记忆层 | 留存 / 日常使用 / 数据积累 | v0.2（对话 + 4 字段沉淀） |
| **输出侧（C）** | 履历生成端 | 变现 / 关键价值兑现 / Demo 杀手锏 | v0.2（周报 workspace 雏形） |

**两条腿相互依赖**：D 沉淀的质量决定 C 输出的天花板；C 输出的价值反向驱动 D 的留存。

---

## 差异化（vs agent memory 产品）

| 维度 | Agent memory 产品 | cockpit（要走） |
|---|---|---|
| **服务对象** | Agent（提供 memory API） | **人**（提供 productivity 闭环） |
| **记忆颗粒度** | 对话事实级（"用户在第 3 轮说了什么"） | **任务/项目级**（"用户完成了 X 项目，实现了 Y 价值"） |
| **输入** | 任意 agent 的对话流 | 项目/任务/对话/完成时的成就沉淀 |
| **输出** | Memory 检索片段 | **履历文档**（周报/月报/年终/CV） |
| **价值兑现** | 解决"agent 怎么记住" | **解决"人怎么从记忆里产生价值"** |
| **商业模式** | 基础设施/API 计费 | 待验证（个人订阅 / 加密跨设备增值 / 个人职业服务） |

**协同姿势**（重要）：cockpit 可以适配 mem9 或其他检索能力以降低实现成本，但它们始终是可替换的辅助能力；本地成就库、核心查询与本地报告必须在断网时可用。cockpit 专注"工作流 → 履历"的产品层，不抢 memory infrastructure 市场。

## 阶段路线

| 版本 | 目标 | 关键交付 | 验证标准 |
|---|---|---|---|
| **v0.3** | 沉淀智能化 | 4 字段 AI 润色 + 智能追问 + 经授权触发的候选建议 + cv_status 三态 | 用首要画像自用 2 周、评估 20 条真实沉淀；≥70% 经轻改后可入库，0 条已确认的事实编造 |
| **v0.4** | 成就库升级 | 个人全局时间线 + 跨项目 CV 视图 + 成就统计/筛选 | 用真实成就各生成 1 份周报和月报；可直接采用的内容比例 ≥70% |
| **v0.5a** | **MCP 集成** | 让 Claude Code / Cursor 等 agent 经用户授权调用 cockpit | 用户可在已授权的 agent 对话中查看并确认 cockpit 写入动作，且所有写入可审计 |
| **v0.5a.1** | **接入中心** | `/integrations` 一键注册到 Claude Code / Cursor / Trae / Cline / Continue / WorkBuddy，不用手改 JSON | 用户在 cockpit web 点 1 下按钮完成配置，5 个 json agent + 1 个 command agent |
| **v0.5b** | **Git 集成** | 用户授权仓库的 commit → 带 commit 证据的成就候选草稿 | 一次 commit 后生成可核验候选；用户确认后才入成就库 |
| **v0.6** | 智能提炼 | 从用户授权的对话/工作历史识别可沉淀候选，并显示来源证据 | 一周授权历史可生成覆盖 ≥80% 已确认成就的周报草稿；记录候选确认率与误报率 |
| **v0.7** | 统一输出引擎 | 周报/月报/年终/CV 共用成就库 | 4 种形态都能一键生成；每种输出的可直接采用比例 ≥70%，生成草稿耗时 <5 分钟 |
| **v1.0** | **VC-ready** | 10 分钟 demo + 个人商业模式 + 增长策略 | 1 个 3 分钟 demo 视频；5 个种子用户在 30 天内各完成至少 3 次"沉淀 → 输出"价值循环 |

**v0.5 拆 a/b 的理由**：MCP 跟 Git 集成是正交的两件事，混在一个版本里会让 v0.5 范围模糊、回归压力大。拆开后可以并行/串行，灵活度更高。

## 核心产品哲学：一次沉淀，多次输出

> "周报像是小型的月报、月报像是小型的年终总结"

翻译成产品语言：

```
                    ┌─ 周报模板（时间窗 7d, 简洁）
                    │
成就库（单一数据源）─┼─ 月报模板（时间窗 30d, 中等）
  (项目+任务+       │
   成就+复盘)       ├─ 年终模板（时间窗 365d, 详细）
                    │
                    └─ CV 模板（时间窗 N 年, 成就导向）
```

**这意味着**：
- 采集侧要保证成就库质量，并保留每条候选的来源证据与用户确认
- 输出侧复用同一数据查询与模板基础设施；新增一种输出形态的边际成本显著低于重建一套采集系统
- 新增一个输出形态（OKR 复盘 / 述职答辩稿）需要模板、事实校验和真实场景验证，而不是只写一段 prompt
- 用户价值随可复用成就资产累积而增强：每多一份高质量资产，就多一份可被不同输出安全调用的素材

### 当前运行时契约（2026-08-11）

- 成就状态为 `pending`、`needs_data`、`ready`；只有用户确认最终 CV 且证据充分的 `ready` 可进入正式输出。
- `/report` 是周报、月度总结、述职与 CV 的统一入口；输出由本地 Composer 生成，不依赖模型可用性。
- 设置中的“数据与备份”可导出 `cockpit-career-memory`，导入先预览后确认，且不会导出密钥或覆盖冲突数据。

## Agent 角色（产品 + 技术 + 商业）

cockpit 在这个目标推进过程中，**Agent 同时承担 4 个角色**：

| 角色 | 职责 |
|---|---|
| **产品专家** | 定义"一次沉淀多次输出"哲学、UX、模板系统；洞察用户真实需求 |
| **技术专家** | MCP 协议集成、成就库 schema、跨项目时间线、模板引擎；架构选型、风险评估 |
| **差异化顾问** | 盯紧 cockpit vs mem9 的边界（人 vs agent / 文档 vs 片段），防止漂移 |
| **打工人** | 自己作为目标用户画像，先用 1 个月，每周一份周报 + 1 份月报 |

## 风险点（提前暴露，不藏着）

1. **外部记忆能力依赖** — 必须坚守"服务人 / 输出文档"差异化；任何检索提供方都可替换，不能成为本地核心能力的前置条件
2. **本地优先 vs VC 故事** — 商业化时必须补账号/云端/支付，但又不能丢本地优先初心（**"本地版是品牌护城河，云端版是变现引擎"**）
3. **LLM 成本** — 智能提炼 + 多模板生成，每份履历都要过 LLM，单次成本要做账（v0.7 之前先用便宜模型）
4. **单兵作战速度** — VC 故事要"快"，但很多环节（UX 打磨 / 种子用户运营）不能跳过；需要平衡"快"与"扎实"

## 回看节奏

每个 v0.X 完成时做一次"目标健康度"复盘，复盘时问三件事：

1. **这版达成了什么？** — 验证标准是否达标
2. **路线是否要调整？** — 哪个里程碑要前置/后置/砍掉
3. **下个分叉要不要先定？** — 哪些待定项变成必须决策
