# v0.4.2 跨项目 CV 视图 — 设计稿

> 立：2026-08-02 | 状态：实施完成（待 self-validate）

## 目标

兑现 GOAL.md 核心哲学"一次沉淀，多次输出"——在"输出"端的第一步：

> 用户从成就库（按项目分组）切到"我所有 ready 成就拉成一份简历"。

不调 LLM，纯结构化展示 + markdown 导出。是 v0.7 统一输出引擎的**基础版**。

## 关键设计决策

### 1. 页面位置：`/cv` 不是 `/achievements/cv`

| 选项 | 优点 | 缺点 |
|---|---|---|
| `/achievements/cv` | 路径体现层级 | 表达"CV 从属于成就"——其实它是"成就库的另一个维度视图" |
| **`/cv`** ✅ | 跟 `/achievements` / `/report` / `/pr` 并列 | 路径更短更突出 |

跟 `/report` 类似的并列结构：成就库是"沉淀"，周报/CV/PR 都是"输出"。

### 2. 不调 LLM

v0.4.2 是"基础版"——纯结构化拼装，不调 LLM。
LLM 润色 + 多模板切换留给 v0.7 统一输出引擎。

**理由**：
- 跟 /pr 区分（/pr 调 LLM 生成 4 段 markdown，/cv 是用户自己拼的）
- 零 LLM 成本 = 拉得快、便宜
- v0.7 升级路径清晰——直接加 LLM 调用

### 3. 双栏布局（成就列表 + markdown 预览）

- **左**：成就列表（按时间倒序，每条含项目 emoji + 标题 + 日期 + cv + tags）
- **右**：实时 markdown 预览（用户操作立刻看到结果）

**为什么双栏**：
- 单一列表看不到"导出会是什么样"
- 单 preview 看不到"哪条成就在哪"
- 双栏 = "操作 ↔ 结果"即时反馈，符合"5 分钟搞定周报"的产品哲学（PRD 场景 4）

### 4. 范围预设：1y / 2y / 3y / 全部

为什么不只"全部"？
- 大部分人写简历/述职只看最近 1-3 年
- 太多旧项目反而稀释"核心成果"突出度
- 4 个预设覆盖 95% 场景，复杂筛选留给 v0.4.3 统计视图

### 5. 模板系统：`web/lib/cv-template.ts` 跟 `web/lib/templates.ts` 分开

- `templates.ts`：周报 / 述职（按时间窗口 + 调 LLM）
- `cv-template.ts`：CV（按时间倒序 + 不调 LLM）

**为什么分开**：
- 两者模型不同（CV 是"全量 ready 拉成一份" vs 周报是"时间窗口 + 模板套"）
- cv-template 简单到不需要 TEMPLATES 数组——单一函数即可
- v0.7 统一输出引擎会重新整合两者

### 6. 端到端测试：`mjs` 脚本模式（跟 test-theme-core.mjs 一致）

不用 vitest，直接用 `--experimental-strip-types` 跑 ts 文件。理由：
- 零额外依赖
- 跟项目里现有 mjs 测试同模式
- 23 个测试覆盖纯函数，0 React/DOM 依赖

## 实现细节

### `cv-template.ts` API

```ts
type CvRangePreset = "1y" | "2y" | "3y" | "all";

function rangeToSince(preset: CvRangePreset): string | null
function filterByRange(items: Achievement[], preset: CvRangePreset): Achievement[]
function generateCvMarkdown(items: Achievement[]): string
```

**内部**：
- `sortByDateDesc` — 内部按日期 desc 排
- `groupByProject` — 内部按项目分组（不导出）

### `cv/page.tsx` 状态

```ts
const [rangePreset, setRangePreset] = useState<CvRangePreset>("all");
const [search, setSearch] = useState("");
const [copied, setCopied] = useState(false);
```

**注意**：search 和 rangePreset 是**前端**过滤，不发请求——`/api/achievements?cv_status=ready` 一次拉全量，客户端过滤。
**理由**：成就是低频增长（每周 N 条），拉全量不贵；用户即时过滤体验更好。

### markdown 输出格式

```markdown
# 成就清单

> 生成时间: 2026-08-02 · 累计 23 条 ready 成就

## 项目 A

- **2026-07-01** · A 任务
  A cv
- **2026-06-01** · A 任务 2
  A2 cv

## 项目 B

- **2026-08-01** · B 任务
  B cv
```

**关键**：
- 标题 + 简介（生成时间 + 数量）
- 项目按"项目内最早日期 desc"排（最近做的项目最显眼）
- 项目内按日期 desc 排
- 每条成就：日期 + 任务标题 + CV（缩进显示层级）

## 风险

| 风险 | 应对 |
|---|---|
| LLM 成本（v0.7 才有） | v0.4.2 零 LLM 成本，**仅纯前端 + 一次 API 拉取** |
| 大量成就拉取慢 | 拉全量不分类 → 一次 100 条内基本 < 200ms（SQLite 性能） |
| 旧项目干扰简历 | 范围预设 1y/2y/3y 给用户控制感 |
| 空项目名 | 兜底 `(未命名项目)`（防止项目被删后成就孤立） |
| 用户找不回某些成就 | 搜索框 + 范围预设双保险 |

## 不做的（明确范围）

- ❌ LLM 润色（v0.7 统一输出引擎）
- ❌ 多模板切换（v0.7）
- ❌ 跨项目 / 按标签筛选（v0.4.3 统计视图时做）
- ❌ CV 评分 / 简历适配度（v0.3.4 润色质量升级时做）
- ❌ 导出 PDF（永远不做——markdown 是用户能控制的格式）

## v0.4.2 → v0.7 升级路径

v0.4.2 的"无 LLM markdown 导出"是 v0.7 的"基础模式"：

```
v0.4.2: 单一模板 + 无 LLM
   ↓
v0.7: 多模板 + LLM 润色 + 用户选模板
   ↓
v1.0: 跟周报/月报/年终共用同一套模板系统
```

`web/lib/cv-template.ts` 的 `generateCvMarkdown` 在 v0.7 会变成"无 LLM 模式"的实现，v0.7 加 LLM 模式时并行。
