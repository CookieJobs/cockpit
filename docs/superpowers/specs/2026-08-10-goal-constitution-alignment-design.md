# Goal 与项目宪法对齐：设计说明

## 目标

让 `docs/GOAL.md` 的产品叙事、阶段路线与可验收标准，和 AI 宪法的“服务人、本地优先、用户掌控、沉淀优先”原则一致；同时消除 `cv_status` 状态说明与已实现系统的漂移。

## 修改范围

### `docs/GOAL.md`

- 采集能力使用“用户授权的来源 → 带证据的候选草稿 → 用户确认入库”描述，明确 Cockpit 不自主替用户写入职业资产。
- 商业化只保留面向个人的订阅、跨设备增值和个人职业服务，删除团队版。
- 将 Git 输入定为成就候选，而不是自动创建任务。
- 将 mem9 表述为可选的、可替换的检索适配方；本地成就库和核心输出不可依赖它。
- 在 v0.3 前锁定首要种子用户画像。
- 用可采纳率、事实准确性、完成耗时、候选确认率等指标替换主观或与宪法冲突的指标。
- 将“零边际成本”和“指数级价值”改成共享数据源带来显著边际成本下降的可验证主张。

### `AGENTS.md`

- 将 `cv_status` 说明从两态更新为 `ready / needs_data / pending` 三态。
- 说明状态由统一写入边界根据证据完整性决定，入口不能以传参绕过质量门槛。

## 不修改的内容

- 不改数据库 schema、状态机、MCP 工具或前端行为。本次是文档与既有实现的对齐。
- 保留 MCP 接入：外部 agent 是用户授权的采集渠道，不是 Cockpit 的服务对象或自主决策者。
- 保留 `cv_status` 三态；代码、MCP、测试与近期 changelog 已以此为准。

## 验收

1. `GOAL.md` 不再出现“团队版”或将 DAU 作为核心指标的表述。
2. 自动化相关条目均具有授权、证据或确认边界。
3. `GOAL.md` 与 `AGENTS.md` 都明确三态 `cv_status`，且不与 `CVStatus` 实现冲突。
4. 使用文本搜索和 diff 检查确认变更仅限本次文档对齐范围。
